- Call Gemini models using Google Native API format
- Supports synchronous and streaming generation methods
- Minimal parameters for quick start

## Usage Examples

### Generate Content

Endpoint:

```text  theme={null}
POST /v1beta/models/gemini-3-flash-preview:generateContent
```

Request body:

```json  theme={null}
{
  "contents": [
    {
      "role": "user",
      "parts": [
        {
          "text": "Summarize the goals of the new night mode in one sentence."
        }
      ]
    }
  ],
  "generationConfig": {
    "maxOutputTokens": 256,
    "temperature": 0.7
  }
}
```

### Stream Generate Content

Endpoint:

```text  theme={null}
POST /v1beta/models/gemini-3-flash-preview:streamGenerateContent
```

Request body:

```json  theme={null}
{
  "contents": [
    {
      "role": "user",
      "parts": [
        {
          "text": "Generate 5 short feature names for an AI writing assistant."
        }
      ]
    }
  ],
  "generationConfig": {
    "maxOutputTokens": 256
  }
}
```

### Multimodal Input

```json  theme={null}
{
  "contents": [
    {
      "role": "user",
      "parts": [
        {
          "text": "Describe the image and write concise alt text."
        },
        {
          "inlineData": {
            "mimeType": "image/png",
            "data": "BASE64_IMAGE_DATA"
          }
        }
      ]
    }
  ]
}
```

## Notes

* Use `generateContent` for complete JSON responses.
* Use `streamGenerateContent` for streaming generation.
* Put text instructions before multimodal parts when possible.

## Response

`generateContent` returns the Gemini `GenerateContentResponse` object directly, without a `code` / `data` wrapper. Text is in `candidates[].content.parts[].text`, and token counts are in `usageMetadata`. Thinking models can add parts with `thought: true` or `thoughtSignature`; skip parts that have no `text`.

## Streaming

`streamGenerateContent` returns `text/event-stream`. Each event is a `data:` line with a partial `GenerateContentResponse`, and the stream ends with `data: [DONE]`. The `alt=sse` query parameter is accepted but not required.

```text
data: {"candidates":[{"content":{"parts":[{"thought":true}],"role":"model"}}],"usageMetadata":{"promptTokenCount":260,...}}
data: {"candidates":[{"content":{"parts":[{"text":"OK."}],"role":"model"}}],"usageMetadata":{"candidatesTokenCount":2,...}}
data: {"candidates":[{"content":{"parts":[{"thoughtSignature":"..."}],"role":"model"},"finishReason":"STOP"}],"usageMetadata":{...}}
data: [DONE]
```

- Concatenate the `text` parts in order. The last event carries `finishReason`.

## Errors

- `401`: missing or invalid API key.
- `400`: invalid request, or the model is not a Gemini model. The body uses the Google error shape: `{"error": {"code": 400, "message": "...", "status": "INVALID_ARGUMENT"}}`.
- `404`: unknown model id.

See [Error Codes](/api-manual/error-codes#llm-endpoint-errors) for example bodies, and [LLM Models](/api-manual/chat-series/overview) for which models support this format.
