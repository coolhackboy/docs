## 3. Creating and Securing Your API Key

Create and manage your API keys on the [API key page](https://poyo.ai/dashboard/api-key).

<Warning>
  **Never expose your API key** in frontend code (browser, mobile apps, public repositories). Treat your API key as a secret.
</Warning>

To help protect your usage, we provide:

- Rate limits per key (hourly, daily, and total usage caps)
- IP whitelist support, allowing only approved server IPs to access the API

These features help prevent accidental overuse and unauthorized requests.

## 4. Required Request Headers

Every API request **must include** the correct headers:

```http
Authorization: Bearer <YOUR_API_KEY>
Content-Type: application/json
```

[Anthropic Messages](/api-manual/chat-series/claude-messages) (`/v1/messages`) also accepts `x-api-key: <YOUR_API_KEY>`, so the official Anthropic SDKs work without changes.

<Accordion title="What a missing or invalid key returns">
  ```json
  {"code":401,"error":{"message":"Invalid API key","type":"authentication_error"}}
  ```

  Always double-check your headers when debugging authentication issues.
</Accordion>

## 5. Make your first generation request

Generation is asynchronous. Submit a task, save its `task_id`, then poll its status or receive a webhook.

<Tabs>
  <Tab title="cURL">
    ```bash
    curl https://api.poyo.ai/api/generate/submit \
      -H "Authorization: Bearer $POYO_API_KEY" \
      -H "Content-Type: application/json" \
      -d '{
        "model": "gpt-4o-image",
        "input": {
          "prompt": "A paper-cut illustration of a city at sunrise",
          "size": "1:1"
        }
      }'
    ```
  </Tab>
  <Tab title="Python">
    ```python
    import os
    import requests

    response = requests.post(
        "https://api.poyo.ai/api/generate/submit",
        headers={"Authorization": f"Bearer {os.environ['POYO_API_KEY']}"},
        json={
            "model": "gpt-4o-image",
            "input": {
                "prompt": "A paper-cut illustration of a city at sunrise",
                "size": "1:1",
            },
        },
        timeout=30,
    )
    response.raise_for_status()
    task_id = response.json()["data"]["task_id"]
    print(task_id)
    ```
  </Tab>
  <Tab title="JavaScript">
    ```javascript
    const response = await fetch("https://api.poyo.ai/api/generate/submit", {
      method: "POST",
      headers: {
        Authorization: `Bearer ${process.env.POYO_API_KEY}`,
        "Content-Type": "application/json",
      },
      body: JSON.stringify({
        model: "gpt-4o-image",
        input: {
          prompt: "A paper-cut illustration of a city at sunrise",
          size: "1:1",
        },
      }),
    });

    if (!response.ok) throw new Error(await response.text());
    const { data } = await response.json();
    console.log(data.task_id);
    ```
  </Tab>
</Tabs>

<Info>
  A successful submit response means the task was accepted, not that generation has finished.
</Info>

## 6. Retrieve the result

```bash
curl "https://api.poyo.ai/api/generate/status/TASK_ID" \
  -H "Authorization: Bearer $POYO_API_KEY"
```

<Tip>
  Continue while the task is queued or running. When it finishes, download the returned files to storage you control. For production workloads, prefer [signed webhooks](/api-manual/task-management/webhooks) instead of frequent polling.
</Tip>

## 8. Data Retention Policy

| Data | Retention |
|---|---|
| Generated media files | Stored for **3 days**, then automatically deleted |
| Billing details and generation history | Stored for **3 months**, then automatically deleted |

<Warning>
  If you need long-term access, make sure to download and store results on your side in time.
</Warning>

## 9. Asynchronous Task Model

All generation tasks on PoYo.ai are **asynchronous**. A successful request returns HTTP 200 and a `task_id`. A 200 response only means the task was created, not completed.

<Steps>
  <Step title="Submit">
    Send the generation request and save the returned `task_id`.
  </Step>
  <Step title="Wait for the result">
    Either provide a callback (webhook) URL in the request, or actively poll the "Get Task Status" API using the `task_id`.
  </Step>
  <Step title="Store the output">
    Download the finished files before the retention window ends.
  </Step>
</Steps>

## 10. Rate Limits & Concurrency

| Default limit | Value |
|---|---|
| New generation requests | **Up to 20 per 10 seconds** |
| Typical concurrent running tasks | 100+ |
| Scope | Per account |

This limit applies to generation tasks submitted to `/api/generate/submit`. LLM endpoints are currently not rate limited.

If you exceed the limit, requests are rejected with **HTTP 429** and do not enter the queue. For most users, this is more than sufficient. If you consistently hit 429 errors, you may contact support to request a higher limit; approvals are handled cautiously.

## 11. Before production

<Check>Keep API keys on your server; never expose them in browser or mobile code.</Check>
<Check>Validate inputs against the selected model's current schema.</Check>
<Check>Handle `401`, `402`, `429`, and transient server failures explicitly.</Check>
<Check>Treat every submission retry as potentially new paid work; confirm whether the original request created a task before resubmitting.</Check>
<Check>Review [task statuses](/api-manual/task-management/status) and [error responses](/api-manual/error-codes).</Check>
<Check>Generated media is temporary. Download results promptly and follow the retention policy shown in your account and API documentation.</Check>
