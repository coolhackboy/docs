## 3. 创建并保护你的 API Key

在 [API Key 页面](https://poyo.ai/dashboard/api-key)创建和管理你的 API Key。

<Warning>
  **切勿在前端代码中暴露 API Key**（浏览器、移动应用、公开代码仓库）。请将 API Key 视为机密信息。
</Warning>

为帮助保护你的用量，我们提供：

- 按 API Key 设置的速率限制（每小时、每天和总用量上限）
- IP 白名单，只允许经批准的服务器 IP 访问 API

这些功能有助于防止意外超额使用和未经授权的请求。

## 4. 必需的请求头

每个 API 请求都**必须包含**正确的请求头：

```http
Authorization: Bearer <YOUR_API_KEY>
Content-Type: application/json
```

[Anthropic Messages](/zh/api-manual/chat-series/claude-messages)（`/v1/messages`）也接受 `x-api-key: <YOUR_API_KEY>`，因此官方 Anthropic SDK 无需修改即可使用。

<Accordion title="缺少或无效的 API Key 会返回什么">
  ```json
  {"code":401,"error":{"message":"Invalid API key","type":"authentication_error"}}
  ```

  排查认证问题时，请务必仔细检查请求头。
</Accordion>

## 5. 发起第一个生成请求

生成是异步的。提交任务，保存其 `task_id`，然后轮询任务状态或接收 Webhook。

<Tabs>
  <Tab title="cURL">
    ```bash
    curl https://api.poyo.ai/api/generate/submit \
      -H "Authorization: Bearer $POYO_API_KEY" \
      -H "Content-Type: application/json" \
      -d '{
        "model": "gpt-4o-image",
        "input": {
          "prompt": "A paper-cut illustration of a city at sunrise",
          "size": "1:1"
        }
      }'
    ```
  </Tab>
  <Tab title="Python">
    ```python
    import os
    import requests

    response = requests.post(
        "https://api.poyo.ai/api/generate/submit",
        headers={"Authorization": f"Bearer {os.environ['POYO_API_KEY']}"},
        json={
            "model": "gpt-4o-image",
            "input": {
                "prompt": "A paper-cut illustration of a city at sunrise",
                "size": "1:1",
            },
        },
        timeout=30,
    )
    response.raise_for_status()
    task_id = response.json()["data"]["task_id"]
    print(task_id)
    ```
  </Tab>
  <Tab title="JavaScript">
    ```javascript
    const response = await fetch("https://api.poyo.ai/api/generate/submit", {
      method: "POST",
      headers: {
        Authorization: `Bearer ${process.env.POYO_API_KEY}`,
        "Content-Type": "application/json",
      },
      body: JSON.stringify({
        model: "gpt-4o-image",
        input: {
          prompt: "A paper-cut illustration of a city at sunrise",
          size: "1:1",
        },
      }),
    });

    if (!response.ok) throw new Error(await response.text());
    const { data } = await response.json();
    console.log(data.task_id);
    ```
  </Tab>
</Tabs>

<Info>
  提交成功只表示任务已被接受，不表示生成已经完成。
</Info>

## 6. 获取结果

```bash
curl "https://api.poyo.ai/api/generate/status/TASK_ID" \
  -H "Authorization: Bearer $POYO_API_KEY"
```

<Tip>
  任务处于排队或运行中时继续等待。任务完成后，将返回的文件下载到你自己控制的存储中。生产环境建议使用[签名 Webhook](/zh/api-manual/task-management/webhooks)，而不是频繁轮询。
</Tip>

## 8. 数据保留策略

| 数据 | 保留期限 |
|---|---|
| 生成的媒体文件 | 保存 **3 天**，之后自动删除 |
| 账单明细和生成历史 | 保存 **3 个月**，之后自动删除 |

<Warning>
  如需长期访问，请及时将结果下载并保存在你自己的存储中。
</Warning>

## 9. 异步任务模型

PoYo.ai 上的所有生成任务都是**异步**的。请求成功时返回 HTTP 200 和 `task_id`。200 响应只表示任务已创建，不表示已完成。

<Steps>
  <Step title="提交">
    发送生成请求，并保存返回的 `task_id`。
  </Step>
  <Step title="等待结果">
    在请求中提供回调（Webhook）URL，或使用 `task_id` 主动轮询“查询任务状态”接口。
  </Step>
  <Step title="保存输出">
    在保留期结束前下载已完成的文件。
  </Step>
</Steps>

## 10. 速率限制与并发

| 默认限制 | 值 |
|---|---|
| 新生成请求 | **每 10 秒最多 20 个** |
| 通常的并发运行任务数 | 100+ |
| 范围 | 按账户 |

此限制适用于提交到 `/api/generate/submit` 的生成任务。LLM 接口目前不限速。

超出限制时，请求会被拒绝并返回 **HTTP 429**，不会进入队列。对大多数用户来说，这个额度已经足够。如果你持续遇到 429 错误，可以联系支持申请提高限制；我们会审慎处理审批。

我们提供顶级、极具竞争力的 API。不过我们并不完美，**整体稳定性可能略低于**官方供应商。这是有意做出的取舍。
