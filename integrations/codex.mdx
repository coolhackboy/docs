# Connect Codex

Codex CLI and the IDE extension read MCP configuration from `~/.codex/config.toml`.

Set `POYO_API_KEY` before starting Codex, then add:

<Note>
  `export POYO_API_KEY=...` or `$env:POYO_API_KEY=...` applies only to the current terminal session. The Codex app and IDE extension do not see it unless they are started from that session or the variable is set at the system or user level.
</Note>

```toml
[mcp_servers.poyo]
url = "https://api.poyo.ai/mcp"
bearer_token_env_var = "POYO_API_KEY"
tool_timeout_sec = 45
```

Start a new Codex session after saving.

<Warning>
  Keep the API key in the environment. Do not put it in the URL or commit it to project configuration.
</Warning>

## Add typed tools

Use a filtered URL when a task benefits from model-specific schemas:

```toml
[mcp_servers.poyo_image]
url = "https://api.poyo.ai/mcp?categories=image"
bearer_token_env_var = "POYO_API_KEY"
tool_timeout_sec = 45
```

See [Choose MCP tools](/integrations/mcp-filtering) for filter behavior and limits.

## Add workflow guidance

The `poyo-ai-models` Agent Skill adds model selection, execution, and task-waiting guidance. It works with MCP or the CLI. To use Codex without MCP, follow the [Quickstart](/integrations/quickstart) with `--agent codex`.

## Verify

Ask Codex: `Use PoYo to check my account, find an image model, inspect its schema and price, and explain how you would run it.`
